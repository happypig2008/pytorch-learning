# AI 使用记录：排错过程10.3

**背景**：今天在尝试将 `d` 类型（差值像素）集成到主循环时，我直接复制了 AI 给的代码片段，结果 PyCharm 一口气报了 25 个红字错误（包括“未解析的引用”、“意外缩进”等）

**排查过程与原因分析**：
1. **未解析的引用 `prev_r`**：AI 给的代码片段调用了 `prev_r`，但并没有提醒我初始化变量。我误以为直接粘贴就行。后来我意识到，Python 需要一个初始值（0,0,0）作为起点，于是我退回到循环外面，补上了 `prev_r, prev_g, prev_b = 0, 0, 0`。
2. **“意外的缩进”报错**：因为我粘贴的代码从不同的位置复制而来，缩进层级（空格数）和当前上下文不匹配。Python 对缩进极其严格，AI 并没有针对我当前的上下文帮我自动排版，导致逻辑块被割裂。
3. **`if/elif/else` 的结构错误**：我最初把 `elif` 写在了 `else` 的后面，并且把状态更新（`prev_r, prev_g, prev_b = r, g, b`）错误地缩进到了 `else` 里面。经过复盘，我才明白：更新状态是公共动作，必须和 `if` 保持同级别。

**收获与反思**：
*   我明白了“变量作用域”的概念：在进入 `for` 循环前，必须先定义 `prev` 变量；每次循环结束，必须更新 `prev`，它就像接力赛的棒子，不能放在条件分支里，否则会漏接。
*   我理解了程序不是“从上到下按行读”的，而是“按块（缩进）执行”的。这是我第一次独立完成从“看报错”到“分析原因”再到“修改缩进”的闭环。
*   这也再次提醒我，AI 给的代码不能直接盲目复制，必须结合自己代码的上下文进行“消化”和“改错”。这个排错过程比直接拿到正确的代码更有价值。

###  任务二开发过程问题复盘（AI使用与排错记录）

## 问题1：画布未定义
- **现象**：程序报错 `NameError: name 'img' is not defined`。
- **原因**：在画图时只写了 `img.putpixel(...)`，忘记在打开文件前创建画布。
- **解决**：在 `w, h = result` 之后补上 `img = Image.new("RGB", (w, h), (0, 0, 0))`。

## 问题2：图片坐标越界
- **现象**：程序报错 `IndexError: image index out of range`。
- **原因**：计算 `x` 和 `y` 坐标时，`pixel_count` 已经提前自增，导致算出的坐标超出了画布边界。
- **解决**：严格保证代码顺序：**先算坐标 (`x`, `y`) -> 再画图 (`img.putpixel`) -> 最后自增 (`pixel_count += 1`)**。

## 问题3：十六进制转换错误
- **现象**：程序报错 `ValueError: invalid literal for int() with base 16: ''`。
- **原因**：在 `parse_pixel_d` 函数中，机械地复制了 `p` 类型的切片 `line[1:3]`。但 `d` 类型只有4个字符，切出来是空的 `''`，无法转换。
- **解决**：将 `d` 类型的切片改为 `line[1:2]`, `line[2:3]`, `line[3:4]`，匹配其单字符长度。

## 问题4：缩进语法错误
- **现象**：程序报错 `IndentationError: expected an indented block`。
- **原因**：把注释或者 `elif` 写在了不合规的缩进层级，破坏了 Python 的代码块结构。
- **解决**：加深了对缩进规则的理解，确保 `if/elif/else` 对齐，代码块内部的缩进严格一致，注释也属于对应的代码块。

## 问题5：文件名后缀与 IDE 误报
- **现象**：文件找不到 (`FileNotFoundError`) 和拼写错误红波浪线。
- **原因**：新建文件时 PyCharm 自动添加了 `.py` 后缀（成了 `small.okti.py`），导致代码找不到文件；`okti` 不是标准英文单词，被 IDE 提示拼写错误。
- **解决**：重命名文件去掉 `.py` 后缀；不盲目修改代码，以终端实际运行结果（退出代码 0）作为正确性的唯一标准。

## 问题6：逻辑代码遗漏
- **现象**：`i` 类型分支运行时画面不对或逻辑无法推进。
- **原因**：在快速复制其他分支代码时，漏掉了 `i` 和 `I` 分支中关键的画图代码和坐标计算。
- **解决**：补齐 `x = ...`、`y = ...`、`img.putpixel(...)`，确保不同像素类型都能被正确渲染。
